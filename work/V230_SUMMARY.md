# v230 界面与交互优化

日期：2026-10-27。沿用现有青绿色与浅色背景，改动限于展示和操作流程；未改存储层，也未访问或改写用户真实账本。

## 已实现

1. **编辑记录**：标题、滚动表单和保存区分离。保存按钮始终可见，关闭/删除按钮至少 44px，支付与价值选项统一轻色样式、勾选标记及读屏状态。可视视口缩短时局部适配；保留冲突检查、草稿确认、保存后位置与焦点恢复。
2. **账单汇总**：总笔数/总金额移到筛选条件下方，始终覆盖全部匹配记录。长账单继续每批 100 笔，回顶按钮按新布局避让导航。
3. **筛选与排序**：多选先暂存，统一“查看结果”；取消或 Escape 放弃临时选择。“重置此项”也需确认应用。日期分两行并支持单边范围，反向日期就地纠错；地点可搜索全部历史候选；排序直接选择四种规则。条件标签整块可清除，面板支持焦点约束、背景滚动锁和键盘视口变化。
4. **首页**：今日消费并入月度概览；预算主要显示余额/超额，支出与总预算作为辅助信息。减少预算卡内部重复警告，原有可忽略提醒规则仍保留。
5. **记账**：压缩可选信息区域的重复边框与间距，选中支付/价值后保持展开，不再突然上移键盘。可手动收起，保留 38px 色块、44px 触控范围、14px 字号和 10px 圆角。金额仍是唯一吸顶区域，键盘仍处于文档流。
6. **统计**：新增月份前后切换和直接选择，历史月按完整月份比较完整上月，当前月截至今天并比较上月同期。分类图例可直达准确的日期/分类账单；返回恢复统计月份、滚动和焦点，同时恢复原账单筛选与已加载批次。图表不可用时分类入口仍可使用。压缩月报入口与分类图表高度。

- `node scripts/validate-release.cjs`：451 项用例通过，含 JS/CJS 语法、JSON、版本链、页面/SW 资源完整性。
- 七组隔离浏览器流程通过：`browser-display.cjs`、`browser-drafts-v229.cjs`、`browser-audit-v229.cjs`、`browser-pwa-v229.cjs`、`browser-performance-v229.cjs`、`browser-edit-v230.cjs`、`browser-ui-v230.cjs`。
- 新 UI 验收覆盖 320/390/430/1280px 无横向溢出；24 个历史地点、多选取消/应用/重置、四种排序、日期字号与反向输入、历史月份、图表降级、统计明细金额一致和返回位置。所有测试使用随机 localhost 端口、新浏览器上下文与合成账本，经 ExpenseDB 写入；读取流程验证账本保持原样。
- 390×844 合成样本：首页预算卡约从 251px 降到 184px，首屏完整显示至少两条最近记录；记账键盘从 y=623 降到 y=535，支付及价值选择后的 y 均保持 535（原累计上移 114px）。编辑保存按钮在 320/390/430px 下均处于 y=784–832，可视视口收缩模拟中处于 y=300–348。
- 编辑实测保存后金额/支付方式写入成功，页面 scrollY=2987 原样恢复，焦点回到原账单；陈旧保存/删除被拒绝，载入最新后仍可保存。首次安装、跨页更新、自动激活说明及离线四视图继续通过。
- 3000 笔合成账单仍只渲染首批 100 行。本机单次首屏约 58ms、搜索事件约 13–17ms；这不是手机硬件性能基准。
- 截图及测量结果保存在未提交的 `output/verification-v230/`。浏览器运行依赖通过 `PLAYWRIGHT_MODULE` 与 `CHROMIUM_EXECUTABLE` 指向已有运行时，无新安装。
