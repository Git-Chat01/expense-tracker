# v229 深度体验审计修复总结

日期：2026-10-26。范围为 v228 审计中已复现的问题。所有浏览器验收使用随机本地端口、全新浏览器上下文和合成账单，没有访问或修改真实用户账本。

## 已完成

| 问题 | v229 行为 |
| --- | --- |
| 两个页面编辑同一笔，旧页面覆盖新版金额 | 保存和删除前核对打开时的完整记录；发现冲突不写入，保留当前草稿，允许确认后载入最新记录。支持 Web Locks 的浏览器串行处理新版编辑页的这些操作。 |
| 货币字段被月报当作 HTML/CSS 解析 | 月报统一转义；新导入和设置拒绝包含 HTML 标记或控制字符的货币字段。已有值仅安全显示，不回填。 |
| 分类 ID 为 `toString` 时习惯统计崩溃 | 索引使用无原型字典，不修改原有分类 ID。 |
| 切页丢失新增草稿 | 当前页面会话内保留整笔草稿，提供带确认的“清空草稿”；保存成功后开始下一笔。 |
| 空表单跨日后误记成昨天 | 页面恢复、前台定时校正和首次输入同步自动日期时间；已有草稿与手动日期不自动覆盖。 |
| 导航或弹层按 Enter 误保存后台表单 | 键盘事件尊重当前控件、输入法和覆盖层；导航 Enter 只执行导航。 |
| 编辑返回跳到列表顶部 | 关闭与保存后保留滚动位置，重绘后恢复原记录焦点；放弃未保存编辑需确认。 |
| 长列表一次创建数万节点 | 首批显示100笔，按需追加；搜索、日期组金额和总汇总仍基于全部匹配记录。中文输入法组合期间不重绘。 |
| 单边日期筛选已经生效但无提示 | 单设起点/终点均显示准确文案、高亮和清除入口。 |
| 未来账单造成首页消费与预算数字难以理解 | 显示“截至今天”与“本月已记”，单列未来预记金额及预算占用；消费节奏只外推已发生金额。 |
| 恢复前自动备份无可用入口 | 数据管理中可只读下载恢复前副本；不覆盖当前账本，不更新“当前账本已备份”时间。 |
| 首次安装或其他页面更新刷新掉草稿 | 首次接管不刷新；其他页面激活新版本时，本页等待主动重载；检测未保存表单后阻止立即更新。 |
| 更新卡错用滞后的更新说明版本 | 与目标 Worker 握手取得实际版本，只显示匹配说明；未同步时明确提示。 |
| 激活时误清理同源其他缓存 | 只清理旧的 `expense-tracker-v数字` 缓存，保留发布状态和其他功能缓存。 |
| 键盘和读屏操作不完整 | 账单行支持 Enter/Space；编辑字段关联标签，编辑与确认弹层限制 Tab 范围、支持 Escape 并恢复焦点。 |

## 数据与兼容边界

- 不清空、迁移、回填真实数据。旧资源路径继续保留，当前页面与 SW 使用新的 v229 真实文件路径。
- 草稿保留范围是当前页面会话中的切页和系统更新保护，不是关闭页面后恢复，也不是跨设备同步。
- 冲突保护覆盖新版编辑/删除入口；旧版已在内存中的页面不会被反向修补。不支持 Web Locks 的浏览器有原值检查，但不承诺同时写入的事务原子性。
- 恢复前副本仅保留最近一次恢复开始前的版本，不是多版本备份历史。
- 已验证隔离 Chromium 手机视口；iPhone 独立 PWA 真机、VoiceOver 尚未实测。该轮为已复现缺陷修复，不构成“系统不存在其他漏洞”的保证。
